# ShipTrace

Deployment tracking service: FastAPI, PostgreSQL 18, one deployable. Early build; see the plan
for the current phase. Read before changing behavior:
`docs/PROJECT_SPEC.md`, `docs/ARCHITECTURE.md`, `docs/IMPLEMENTATION_PLAN.md`, `docs/adr/`.

## Commands

- All gates, needs Docker: `scripts/verify.sh`
- Gates that need no Docker, safe in the sandbox: `scripts/verify.sh --fast`
- Real-process smoke test: `scripts/smoke.sh`
- Owner-run, outside the sandbox: `scripts/p0_gate.sh`, `scripts/check_gates.py`
- Unit tests only: `uv run --frozen pytest tests/unit -q`
- Check Claude config and docs links only: `python3 -I scripts/check_repo.py`
- Test hooks: `python3 -I .claude/hooks/tests/test_hooks.py`

## Non-negotiables

- Spec is scope. A feature absent from `docs/PROJECT_SPEC.md` needs a spec change, approved first.
- Work in vertical slices. Write the failing test first for significant behavior, and see it fail.
- Never state that something passed unless it ran in this session. Add commands and results to
  `docs/engineering/VERIFICATION_LOG.md`.
- A security property is claimed only with evidence. `docs/security/ASVS_ASSESSMENT.md` starts
  each item as `Planned`, not `Pass`.
- Tests must be able to fail. If a test stays green with its target code broken, it is not a test.
- Prefer clear code. No abstraction without a current second use or a stated test need.

## Layers

`api` → `application` → `domain`; `persistence` → `application` → `domain`. `domain` is pure
stdlib with no clock or I/O. Do not add exceptions; change the ADR first.

## Data invariants

- `deployments` and `deployment_events` are append-only. The runtime role has no `UPDATE`,
  `DELETE` or `TRUNCATE` on them.
- Status is derived from events. Do not add a status column.
- Clients never supply timestamps.
- Applied migrations are immutable. Add a new one.

## Approval boundary

Hooks block these, and that is intended. Do not work around a block by indirection. Ask the
owner, who can run the command with `! <command>`:

`git push`, `gh` writes, `docker push`, `aws`, Terraform changes. Local merges are not hook-blocked;
do not merge into `main` without approval.
Never touch unrelated repositories, credentials or cloud accounts.

## Commits

Format: `<type>(<scope>): <description>` per Conventional Commits 1.0.0. `scripts/commit_msg.py`
enforces this as a `commit-msg` hook, and
`scripts/pre_commit.py` checks staged content. Install both once with `scripts/install_git_hooks.sh`.

Claude Code commits only with `scripts/commit.py "<message>" <path>...`, from the root, approved
each run. `.git` is read-only in the sandbox, so do not stage there; the script stages the paths.

- Types: `feat fix refactor test docs chore ci build perf security`. Lowercase type and scope.
- Imperative, concise description, under 72 characters. One logical change per commit.
- No generic messages such as `updates`, `fixes` or `WIP`.
- No AI attribution of any kind: no `Co-authored-by` trailers for an AI, and no "generated by" or
  "AI-assisted" text in commits, PR descriptions or project documentation.
- Use the existing Git identity. Never pass `--author` or `--reset-author`, and never amend to
  change attribution.
- Verify the message and trailers before committing. Never push, rewrite history or create a
  release without explicit approval.

Every commit must be signed with the owner's existing GPG key through the existing `gpg-agent`:

- Never disable signing: no `--no-gpg-sign`, `-c commit.gpgsign=false` or equivalent, and never an
  unsigned fallback commit.
- If signing fails, stop and report that the key must be unlocked manually. Never request, read,
  store, log or handle the passphrase. Never export keys or change key protection.
- Never change the signing key or Git identity without approval.
- After each commit, verify with `git log -1 --show-signature`.

## Workflow

- `/plan-slice` before a slice; `/verify-slice` before calling it done.
- At phase gates: `/security-audit`, plus `/migration-review` for schema changes and
  `/release-readiness` before a release.
- Reviewers report findings and change nothing. Confirm a finding before fixing it.
- Explain important decisions and the alternatives rejected; the owner is learning from this.
- Stop at each phase gate for owner review.
